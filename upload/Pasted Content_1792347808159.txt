Primary slogan: Imagine. Build. Connect.

# 22. SECURITY AND ROW LEVEL SECURITY

Enable RLS on every exposed application table.

Write explicit SELECT, INSERT, UPDATE, and DELETE policies where required.

PROFILES:
- Users can edit only their own permitted profile fields.
- Public profile views expose only approved fields.
- Users cannot assign themselves privileged roles.

PROJECTS:
- Public projects are readable according to public access rules.
- Private projects are visible only to authorized members.
- Owners and authorized managers control project settings.
- Clients cannot assign ownership to another user.

PROJECT MEMBERS:
- Users cannot make themselves owners or administrators.
- Role changes require appropriate authorization.
- The final owner cannot be accidentally removed.
- Ownership transfer must be explicit and auditable.

TASKS:
- Access follows project visibility and membership.
- Task changes require the appropriate project role.
- Assignment is restricted to eligible members.

COLLABORATION REQUESTS:
- Applicants access their own requests.
- Authorized project managers review applications.
- Requesters cannot approve their own requests as project managers.
- Membership creation must be safe and atomic.

COMMENTS:
- Reads follow project visibility.
- Mutations require authorization.
- Input must be length-limited and safely rendered.

LIKES AND SAVES:
- Users manage only their own records.
- Duplicate actions are prevented by constraints.
- Private projects remain private.

NOTIFICATIONS:
- Users can read and update only their own notifications.
- Trusted event creation cannot be forged by the client.

REPORTS:
- Users can submit reports under rate limits.
- Private moderation information is restricted.

CONTRIBUTIONS:
- Verified awards can only be created through trusted logic.
- Duplicate awards must be prevented.

BLOCKS:
- Users manage only their own block records.
- Blocking restrictions must be applied consistently.

Use SECURITY DEFINER functions only when justified, with a safe search_path and restricted execution permissions.

Never disable RLS to make a feature work.

Never expose a Supabase service-role key in a web bundle, mobile application, public repository, or client-side environment variable.

Use a trusted backend or Edge Function for privileged workflows.
